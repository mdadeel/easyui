# Search and discovery plan

Production website: https://easyui.mdadeel125.workers.dev/  
Repository: https://github.com/mdadeel/easyui

## What the site already supplies

- Static HTML with descriptive titles, page-specific descriptions, component links,
  example source, and human-readable answers; interactive examples load on top.
- Canonical URLs, social image metadata, a sitemap, and `robots.txt` when the production
  `SITE_URL` is set at build time. See [Search Console setup](SEARCH_CONSOLE.md).
- Real component examples, usage notes, and links to the implementation. Selected
  components have hand-checked API and accessibility notes; expand these as the
  library changes rather than making unsupported claims about complete coverage.

Useful, accurate pages and ordinary crawlable links are the foundation for search and
answer engines. There is no guaranteed GEO/AEO markup or special file that causes AI
citation. Google's guidance says normal Search eligibility and SEO fundamentals apply
to its AI features. It also says `llms.txt` is not used by Google Search. Google no
longer shows FAQ rich results, so the visible FAQ is for readers, not a promised rich
result. See [Google's AI features guidance](https://developers.google.com/search/docs/appearance/ai-features)
and [Google's generative AI optimization guide](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide).

## Earn relevant backlinks

The README includes a direct link to the live site once these changes are published.
A repository link is useful attribution and discovery; it does not guarantee ranking
credit. The owner can also set the GitHub repository's **About → Website** field to
the production URL. The automated integration may lack permission to edit that field.

1. Add a link to the project from profiles and project pages you already own, when
   relevant. Keep it accurate and don't create duplicate profiles for link building.
2. Publish an original tutorial showing a real component or pattern and link to the
   relevant detail page and source. Explain what is complete and any limitations.
3. Share useful examples in React communities only where their rules allow it and when
   they answer an actual question. Avoid unsolicited mass posting.
4. Submit the repository to a few curated React/open-source directories that accept
   relevant projects, after reviewing their rules and making sure the project is ready.
5. Ask real users or maintainers of relevant projects for feedback or an independent
   mention; do not demand links or offer compensation for ranking credit.

Example outreach (personalize it, don't bulk-send):

> Hi [name], I built EasyUI, a React component library with live examples and a theme
> playground. I thought the [specific example] might be useful for [specific reason].
> If it's relevant to your readers, I'd welcome feedback or an independent mention:
> https://easyui.mdadeel125.workers.dev/

Avoid buying ranking-passing links, link farms, automated comments, excessive link
exchanges, and misleading endorsements. Paid placements must be appropriately
qualified. See [Google's link spam policy](https://developers.google.com/search/docs/essentials/spam-policies#link-spam)
and [link best practices](https://developers.google.com/search/docs/crawling-indexing/links-crawlable).
No external backlinks have been purchased, published, or claimed by this plan.
